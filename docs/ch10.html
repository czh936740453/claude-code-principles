10 · 自学路线图与实践建议

拿到一份可执行的行动清单：怎么读源码、怎么动手复刻、注意什么边界。

本章目标　拿到一份可执行的行动清单：怎么读源码、怎么动手复刻、注意什么边界。前置依赖　建议学完全部章节。

10 /读源码的三步法

面对几千个文件，别从头读到尾。用三步走：

  1. 找入口先从 cli.js / main / README 找到程序从哪开始跑，画出调用链。
  2. 追数据流盯住「一条用户输入」如何变成请求、如何变成工具调用，把主线走通。
  3. 再看支线主线懂了以后，再去看权限、压缩、配置这些旁路，逐个击破。

10 /最小复刻路线

想自己动手，不要一上来就复刻全部。按这个顺序做，每一步都对应前面章节的封装代码：

  1. 最小代理循环拿第 3 章的 agent_loop.py，把「模拟模型」换成真实 API 调用。
  2. 加工具把第 4 章的 tools.py 接进来：注册表 + 分派。
  3. 加权限把第 5 章的 permissions.py 插在工具执行之前。
  4. 加会话用第 6 章的 session.py 支持断点续聊。
  5. 加 CLI用第 7 章的 cli_repl.py 包一层交互界面。
  6. 加配置用第 8 章的 config.py 让行为可配置。

10 /安全与伦理边界

红线公开源码分析的用途是学习原理，不是照抄发布、也不是用于绕过付费或攻击。别把非公开功能当承诺：代码里有不代表能上线、更不代表官方支持。
  • 版权：源码分析可以谈原理，转载 / 商用要谨慎。
  • 安全：永远不要在 bypassPermissions 下跑不确定的命令。
  • 伦理：不做绕过鉴权、滥用 API 的实验。
  • 预期管理：分析出来的功能随时可能变化或消失。

10 /推荐练习清单

  • 把 agent_loop.py 改成「最多循环 N 次就停止」，观察终止条件的作用。
  • 给 tools.py 加一个自定义工具，比如「统计代码行数」。
  • 用 context_manager.py 打印出压缩前后各占多少 token。
  • 给 cli_repl.py 加一个 /model 命令，模拟切换模型。
  • 把各章封装代码组装成一个完整的最小 CLI 工具。
